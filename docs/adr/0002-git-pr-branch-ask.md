# ADR-0002：Git PR 分支可选

- **日期**：2026-08-21
- **范围**：仓库工作流（不改采集 / 播放契约）

## 1. 要解决什么

单人仓库一直在当前分支上改。功能变大时（例如 Android 采集）可能需要功能分支再合并，但不想把「每次必须开 PR」写成硬规则。

## 2. 背景

Git 里的 **PR = Pull Request**：从主线拉功能分支，改完再合并。不是另一种 commit 格式。本仓库默认在当前分支直接提交。

## 3. 决策

### 决定做

1. **PR 分支可选，默认仍在当前分支改。**
2. 非琐碎改动（新模组、新目录、架构向、多文件功能）可以开功能分支；琐碎改动（文案、错别字）不必。
3. 开了分支也不等于要推远程或在 GitHub 上开合并页。

### 决定不做 / 延后

- 不强制 GitHub Flow，不强制保护 `main`。

## 4. 后果

若以后改为「默认都开分支」或「默认都不要」，再修订本 ADR。
